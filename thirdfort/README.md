# Thirdfort professional web demonstration

Start on the Thirdfort page. Allow analytics, choose **Conveyancing**, follow **Read source of funds guidance**, and open **How can we handle a gifted deposit alongside savings?** Choose **Ask about mixed deposits**. In the live Messenger, send a fictional question about a gift and a buyer’s savings, choose **Source of funds**, then **Speak to professional support**. In the scripted rehearsal, choose the example question and **Ask a professional adviser**. The rehearsal comparison route selects **That answers my question**. The professional portal and integrations routes can start directly from the support section. The app-support link points people completing a check to the separate Thirdfort help centre.

Add `?presenter=1` to see the consent state, chronological browser events, locally derived segments and outcomes below the footer. **Reset this visit** clears the website preview. It leaves the provider session alone. Local events are held in browser memory and cleared when analytics is declined or reset. The visitor can open the scripted rehearsal after declining analytics.

Provider setup uses a separate professional inbound flow and queue. A suitable first request is a fictional conveyancer asking how a mixed gift and savings deposit appears to the firm. The AI can explain the public product workflow with a source. A case-specific interpretation, access to a report or an account detail belongs with professional support or the authenticated portal. For a firm evaluating Thirdfort, keep implementation and integrations distinguishable from existing client support. The published phone deployments are the app-user channel.

| Predictive Engagement segment | Event name | Website condition |
| --- | --- | --- |
| Thirdfort Web - Conveyancing source of funds | `tf_context_offer_shown` | Conveyancing section viewed and mixed-deposit guide opened during the visit. The site shows one inline professional support offer. |
| Thirdfort Web - Professional portal help | `tf_portal_interest` | The visitor chose professional portal help. |
| Thirdfort Web - Firm onboarding and integrations | `tf_integrations_interest` | The visitor chose firm onboarding or integrations. |
| Thirdfort Web - App support signpost | `tf_app_support_selected` | The visitor chose the app support route. Exclude this group from professional proactive offers. |

All site events carry `surface=thirdfort_professional_web` and at most an allowlisted page or topic. See [journey.mjs](journey.mjs) for event names and [messenger.mjs](messenger.mjs) for the adapter. Native browser events are section views, guide expansion, the context offer, messaging opens and the app support signpost. Use provider flow milestones or interaction data for native topic selection, AI invocation and exit reason, customer-confirmed help, adviser transfer requested, actual queue answer, and final wrap-up. A messaging open or adviser request is a separate event from a queue answer.

The dedicated inbound flow and guided bot are published. **Thirdfort Professional Web**, Messenger configuration version 1, has Messaging and Digital User Tracking enabled, with attachment uploads and the built-in launcher off. The four Genesys segments match the exact web event names above and expire after one day. Live Now showed the conveyancing segment and web visit in the Chrome rehearsal. Interaction Analytics showed the guided bot and the transfer to **Thirdfort Professional Support**. Adviser pickup and the linked journey in the agent view are still to be verified.

The standalone site is served at [demo-thirdfort.simonridd.com](https://demo-thirdfort.simonridd.com/) by the `demo-sites-thirdfort` Cloudflare static Worker. Its public Messenger ID and exact origin are in `messenger-settings.mjs`. Environment Builder owns the deployment lifecycle. Activate that deployment for a live rehearsal. The GitHub Pages copy uses the scripted rehearsal because its origin differs from the registered origin.

For a fictional attended enquiry, open its Customer Journeys tab and verify website context and the interaction outcome. Check tracking decline, one unanswered enquiry and the app support signpost separately. The current bot is guided. Include an AVA session trace once an AVA is connected and exercised.
